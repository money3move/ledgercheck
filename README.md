# ledgercheck

**总数对得上不算数，每笔都要能追到来源。**

`ledgercheck` 按对齐键比较两份账目明细，逐条定位差异，
并给出多种口径的合计与差异归因。

- 零依赖，Python 3.10+ 标准库即可运行
- 单文件，`ledgercheck.py` 拷走就能用
- 只读 CSV，不修改任何文件

## 安装

零依赖，Python 3.10+ 即可：

```bash
pip install money3move-ledgercheck
```

装完直接用命令名调用：

```bash
ledgercheck --help
```

也可以不用安装，直接把 `ledgercheck.py` 拷走用——它只依赖标准库。

## 为什么需要它

账目最耗神的地方不是加总，而是**解释**。

两份表加起来一样，明细却对不上，差在哪儿没人说得清——
这种情况通常意味着有一笔金额被归错科目，或者有一行根本没进系统。

`ledgercheck` 的重心因此不在算合计，而在**定位差异**。它把两份明细按某个键对齐，
逐条比出三类：

- **只在 A 有**——这一笔可能漏了
- **只在 B 有**——这一笔可能多算了
- **金额不同**——同一笔金额变了

另外有一条硬规则：**来源追不到的金额单独列出，不并进任何合计。**
金额为空、无法解析成数字、对齐键重复或为空的行，都归入「来源缺失」，
不参与合计，也不参与差异归因。

## 用法

```bash
# 基本用法
python ledgercheck.py --a 十月.csv --b 十一月.csv --key id

# 指定金额列与容差
python ledgercheck.py --a a.csv --b b.csv --key invoice --amount amount --tolerance 0.01

# 机器可读输出
python ledgercheck.py --a a.csv --b b.csv --key id --json
```

输出：

```

A 共 24 行（有效 23），B 共 26 行（有效 25）
键能对上： 22 条

差异分布：
  只在 A 有：1 条
  只在 B 有：3 条
  金额不同：  1 条

  INV-1043    340.00
  INV-1051     88.50
  INV-1055    512.00

金额不同的条目：
  INV-1033    A=100.00  B=150.00  差=50.00

来源缺失的条目（不并入任何合计）：
  A 第 7 行：金额缺失或无法解析
    键 INV-1021 的金额字段为空或不是数字

合计（多种口径）：
  A 全部有效行合计：   15840.00
  B 全部有效行合计：   16780.50
  两者差：             940.50
  仅两边共有的键合计： 15640.00

差异归因：
  金额不同贡献： 50.00
  只在 B 有：     940.50
  只在 A 有：     1200.00

  残差应接近 0。若不为 0，说明还有未被分类的差异，通常来自来源缺失的行或浮点误差。
```

**残差接近 0 是关键信号**：说明所有差异都被归因到了具体条目上。
如果残差明显不为 0，就说明还有没被分类的差异——多半来自来源缺失的行。

## 多种口径的合计

因为「合计」本身就有歧义，`ledgercheck` 给三个口径：

| 口径 | 含义 | 什么时候看它 |
|---|---|---|
| A / B 全部有效行合计 | 各边能解析出金额的所有行 | 想知道两边总额差多少 |
| 仅两边共有的键合计 | 只算键能对上的部分 | 想排除「多了一笔/少了一笔」的影响 |
| 差异归因 | 金额不同 + 只在 B + 只在 A | 想确认差异是否被完全解释 |

## 已知局限

- **要求两份文件表头一致**。列名不同会导致对不上，工具不会做列名映射。
- **只认 CSV**。Excel 的 `.xlsx`、TSV 都不支持，先转成 CSV 再来。
- **只支持 UTF-8（含 BOM）**。GBK 文件请先转换，工具会给出转换命令的提示。
- **金额列靠猜**。按 `amount`/`money`/`price`/`total`/`金额`/`费用` 等常见名匹配，
  猜不到时会报错要求你用 `--amount` 指定，不会随便挑一列。
- **金额解析简单**。只处理数字、千分位逗号、`¥`/`$`/`RMB` 与括号负数；
  不处理「约」「左右」这类带文字的金额。
- **不做科目归类的合理性判断**。同一笔被归到哪个科目，它只按对齐键比，不评价归类对不对。
- **不使用浮点数**。金额全部用 `Decimal`，避免浮点误差混进差异判断。
- **不做币种换算**。两份文件币种不同的话，比较结果没有意义。

## 为什么还要做这个

表格软件里的「合并单元格 + 透视表」能给出总数，但不会告诉你**差在哪**。
而账目工作里，真正花时间的永远是这一步。

`ledgercheck` 把差异分类这件事固定下来：
三类差异各归各位，来源缺失的单独隔离，最后给一个残差告诉你——
**是不是每一分钱的差异都被解释清楚了。**
